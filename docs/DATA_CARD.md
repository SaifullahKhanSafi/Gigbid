# Data card and attribution

## Selected real-world source

**asaniczka, Upwork Job Postings Dataset 2024 (50K Records), version 1, Kaggle.** <https://www.kaggle.com/datasets/asaniczka/upwork-job-postings-dataset-2024-50k-records>. Metadata retrieved through Kaggle's public API on 2026-11-15 identifies **ODC Attribution License (ODC-By)**. License reference: <https://opendatacommons.org/licenses/by/1-0/>. Attribution applies to derived statistics as well as source data. This project uses a third-party snapshot; it does not scrape Upwork.

The raw ZIP checksum, CSV checksum, exact row counts, exclusion counts and derived statistics are recorded in `evals/results/data_acquisition.json` and `real_data.json`. Raw files and processed job text are ignored by Git. Reproduce acquisition with `python -m scripts.fetch_datasets --slug asaniczka/upwork-job-postings-dataset-2024-50k-records --download`, then `python -m scripts.prepare_real_data`.

Fields: title, description, publication timestamp, hourly indicator, hourly lower/upper bounds, fixed budget and country. Missing client histories, real Connects costs, freelancer experience, application outcomes and fraud labels remain unknown. The local simulator does not turn those unknown fields into real observations.

Processing: HTML unescape, tag/whitespace normalization, deduplication by source job identity (fallback content hash), removal of very short records, masking detected email/phone/account strings, conservative parsing of skills from RSS text, stable chronological train/holdout split. Only the training portion contributes price statistics. Positive hourly bounds become midpoints or a single available bound; reversed bands and rates outside USD 1-500 are excluded. Fixed budgets are never combined with hourly rates. USD is inferred from dataset dollar notation, not independently currency-verified.

These are posted historical budgets, not market-clearing wages or successful bids. Broad keyword categories are heuristic and may overlap; first matching category wins. Historical timing, platform coverage, noisy descriptions and third-party collection methods limit representativeness. Masking is pattern based and can miss names, addresses, unusual account formats or obfuscated contact details. Do not publicly redistribute raw text without your own review of applicable rights.

## Synthetic material

All personas, projects, case studies, CVs, READMEs, code outlines, reviews, proposal outcomes, local clients, histories, Connects costs, dev job labels and conversations were generated by `scripts/seed_data.py` with a fixed seed. They carry `synthetic: true` and a provenance field. None represents the student's actual experience. The starter ZIP's sample records were not copied.

`data/processed/manifest.json` records generated counts and a corpus checksum. Every fictional persona has a separate corpus in `data/personas/<persona>/corpus.json`. Proposals' won/replied/ignored labels are independent random draws, not genuine observations. Code records are illustrative outlines, not evidence of production deployments.

The synthetic dev split is separate from historical proposals; it never enters the retriever. However, the generator shares a skills ontology and recurring project templates across corpora and dev jobs. Labels use those same skills/risk definitions. Therefore high retrieval and decision scores are optimistic development checks. They are not independent human judgments, official GigSim outcomes, or hidden test results. Repeated renderings are evaluated at project level so a README/code/case rendition of the same project counts once. Empty relevance sets are excluded from recall averages and evaluated through abstention/decision tests.

The local simulator replies with a fixed published fixture after an approved proposal. This checks the proposal-to-conversation path; it is deliberately excluded from reply-rate effectiveness claims. Local outcome memory learns synthetic fixture observations only and must not be confused with live success data.

## Model provenance

Qwen 2.5 0.5B, 1.5B and 7B Instruct are open-weight local models from the official Ollama library. These sizes use Apache 2.0 according to the model library; the unused 3B variant has a different research license and was not selected. `sentence-transformers/all-MiniLM-L6-v2` and `cross-encoder/ms-marco-MiniLM-L6-v2` are open embedding/reranking models; the latter's model card declares Apache 2.0. Model versions and measured hardware appear in results files. User-owned existing D: model files were reused; model weights are not committed.

## Missing official data

Official GigSim, the instructor persona corpus, independently labelled dev set, November 2 policy update and hidden set were not supplied. `gigsim/` is reserved and contains no copied/reconstructed instructor implementation. All local substitutes are separately authored. Official evaluation must be rerun once those assets become available.
